## Plain-English Goal

CodeQL is GitHub's security scanner that reads code, builds a searchable database for one programming language at a time, and reports possible security bugs. This repository will use CodeQL in two places:

1. Local developer runs before merge.
2. GitHub Actions continuous integration, which means the checks that run after code is pushed.

The scanner must be careful. It must scan only languages CodeQL supports and only languages that are actually present in the repository. It must not scan Haskell, PostgreSQL migration files, generated files, vendored dependencies, build outputs, caches, or temporary reports.

## Repository Language Inventory

The backend is Python + Rust only (see [ADR 0007](../adr/0007-python-rust-two-language.md)); C/C++ and Go were removed on 2026-06-06. The tracked repository files, after excluding generated files and caches, currently contain:

- Python: present.
- Rust: present.
- JavaScript/TypeScript: present (the Angular frontend).
- C/C++: removed 2026-06-06; no longer scanned.
- Go: removed 2026-06-06; no longer scanned.
- PostgreSQL and SQL migration files: absent from the supported scan set, and CodeQL is not configured for them.

The language list is generated by `scripts/codeql_language_inventory.py` so it changes only when real source files change.

## Behavior

Given the repository has supported source files in Python, Rust, and JavaScript/TypeScript, when a developer runs the local CodeQL command, then the command creates one CodeQL database and one SARIF file per supported language.

Given a language has no tracked source files, when CodeQL runs, then that language is skipped. When tracked files for a supported language are added later, then it is detected automatically and receives its own database and SARIF file.

Given PostgreSQL files exist, when CodeQL language detection runs, then they are reported as unsupported for this repository and are not added to the scan list.

Given CodeQL reports the same finding more than once, when the SARIF importer reads the reports, then only one AutoIssue is created for that CodeQL finding.

Given CodeQL finding evidence is saved to the database, when the importer writes that evidence, then it is stored once in `CodeQLFindingEvidence` as an LZ4-compressed payload. The AutoIssue row keeps only a short readable pointer to that compressed evidence row.

Given any CodeQL-backed AutoIssue is open, when a commit runs the hard checks, then the commit stops until the issue is resolved or explicitly marked reviewed through the normal AutoIssue process.

Given more than 10 CodeQL-backed AutoIssues are open, when the verifier runs, then it stops the commit and prints the oldest 10 open issue identifiers.

## Build Strategy

CodeQL supports build-free databases for the languages this repository scans. With C/C++ and Go removed (2026-06-06), every scanned language uses build-free (`none`) mode and needs no manual build command:

- Python: no build command.
- JavaScript/TypeScript: no build command.
- Rust: CodeQL's Rust extractor mode when Rust is present. The GitHub Action uses `none` build mode for Rust. The local command-line runner lets CodeQL use the Rust extractor default instead of forcing a manual build command.

## Exclusions

The scanner ignores:

- `node_modules`, `.venv`, `venv`, caches, build outputs, coverage outputs, reports, temporary folders, and audit logs.
- Django migration folders.
- generated protocol buffer files such as `*_pb2.py` and `*_pb2_grpc.py`.
- SQL files.

## AutoIssue Shape

Every CodeQL AutoIssue description must include:

- Alert type.
- Affected file.
- Evidence.
- Severity.
- Reproduction command.
- Recommended fix.
- True-positive status, defaulting to `needs review`.

The dedupe key is based on the CodeQL rule id, language, affected file, line number, and message text.

The full finding evidence is stored in the linked `CodeQLFindingEvidence.compressed_payload` field. That payload must always use the LZ4 frame format. The table has a unique finding fingerprint, so repeated imports update the same compressed evidence row instead of saving clones.

## Resource Limits

Local and continuous-integration runs default to:

- `CODEQL_THREADS=2`.
- `CODEQL_RAM_MB=6144`.
- one database per language.
- one SARIF file per language.

Developers can raise the limits only by setting environment variables before running the command.
